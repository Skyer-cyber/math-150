# 内容索引检索规范

本索引用较短的导航和摘要定位需要阅读的原文件，不用摘要替代教材、题目或讲解原文。原件是内容证据；索引是可重建的派生资料。索引是否已完成、哪些页可检索和哪些内容仍待核读，以生成报告和逐文件状态为准，不因本规范存在而默认全部完成。

## 分层读取

`SOURCE_OF_TRUTH.md` 只指明资料域、入口、边界和版本规则，不逐项展开所有原文件。`内容索引/主题/` 按实际读取的正文建立主题入口；文件名提供的候选主题必须与正文证据区分，不能伪装成已阅读结论。

每个原文件有一份 `内容索引/文件/Fxxxx.md` 叶子条目，记录真实路径、完整 SHA-256、文件类型、关联内容和读取状态。相同完整 SHA-256 的原件共用 `内容索引/内容/C_<hash12>.md` 内容卡及 `内容索引/全文/C_<hash12>.json` 全文数据，减少重复抽取与阅读。单文件入口仍保留，不把副本的来源关系抹掉。

主题入口负责引导，叶子条目负责确定文件与版本，内容卡负责提供有页序证据的内容概览，全文数据负责定位连续文本，原件负责最终核读。一次通常只读一个主题入口和少量命中的文件条目，不一次加载全库全文。

## 标识与记录

`Fxxxx` 是原文件身份，不是排名、题号、章节号或版本优先级。首次分配后应保持稳定；新增条目追加，不因排序变化重新编号。授权移动文件时更新路径关系；同路径的字节变化必须重新核对并记录，不能沿用旧内容的哈希和摘要。

`C_<hash12>` 取完整 SHA-256 的前 12 位，只是可读的内容标识。判断字节相同必须比较完整 SHA-256，不能只比较前缀或文件大小；生成时如出现前缀碰撞，停止合并并延长标识，同时更新所有关联。

检索记录的基本字段如下。字段存在不代表相应阅读或核验已完成。

| 字段 | 含义 |
| --- | --- |
| `path` | 相对知识库根目录的实际原件路径，大小写和原文件名保持不变 |
| `file_id` | 每个原文件的 `Fxxxx` 编号 |
| `content_id` | 根据完整 SHA-256 关联的内容标识 |
| `sha256` | 原文件完整 SHA-256，核验时重新读取原件计算 |
| `kind` | 实际文件格式或抽取类型，不代表考种或权威性 |
| `index_path` | 可继续下钻的 Markdown 索引路径，以记录的真实路径为准 |
| `text_path` | 对应页级/区段级全文 JSON 路径 |
| `units` | 实际读取单元及其定位信息；PDF 按页，其他格式按实际区段 |
| `analysis_status` | 该文件实际抽取、摘要分析与待核状态，不得用“成功”掩盖缺页或未校对 |

叶子条目和内容卡的摘要须能追溯到实际阅读单元。内容关系如“此试卷的答案”“同年另版”“合并版包含这些分课”需有原文/页序证据；没有核对过时标为候选关系，不按名称直接确认。

## 查询与核读

先读取知识库导航，按主题确定候选资料域，再运行本地搜索。例如，在知识库根目录中：

```sh
python3 内容索引/scripts/search.py "柯西中值定理" --limit 5
```

单次结果最多 5 条。每条应提供原件路径、`Fxxxx`、对应索引路径、PDF 页序或其他区段、命中证据与 OCR 告警。得分和排列顺序只用于检索相关性，不决定资料权威性；全文命中与仅文件名/摘要命中应明确区分。相同内容可合并展示，但仍应能找到其各原件条目。

选择结果后读取连续完整区段。以下编号和页范围仅示范调用方式，实际使用搜索返回的编号与页序：

```sh
python3 内容索引/scripts/search.py --file F0123 --pages 4-7
```

需要核对来源一致性时使用 `--verify`，以脚本实际报告为准。哈希核验只验证索引对应哪些字节，不验证 OCR、公式、摘要、题解或适用考种正确。

PDF 页序从 1 开始，封面、目录和空白页也占页序；印刷页码不是默认定位键。段落范围是抽取后单元内的定位区段，不应冒充原书段落编号。PDF 原始换行可能拆开一句话或一个公式，不能把自动区段边界当成推理边界。DOCX 没有稳定分页时按段落/表格/公式区段记录；单幅图片按图片文件定位；未真实渲染过的格式不虚构页序。

检索成功不等于阅读完成。具体回答前必须取得并阅读完整核心原文，包括：

- 定义、定理的全部假设、结论、适用范围与例外条件。
- 题目全部已知条件、符号定义、图形信息、问法和题号上下文。
- 相关例题和对应推导的完整逻辑，包括不等式方向、分类讨论、边界点和隐含域限制。
- 与核心区段相连的上一页或下一页，以及它所依赖的前置定义、注释或勘误。

范围由语义完整性决定，不是机械读取命中前后固定两段。如果证明跨页、解析另册或引用前面的定义，沿引用继续读取；完整核心原文读到之前，不依据短摘要讲解、批改、出题或宣称该方法成立。无须每次读取整本教材，但不能为省 token 截掉必要条件或推导。

## OCR 与公式边界

全文 JSON 是本地抽取/识别得到的检索文字，不是新编教材，也不自动等于已人工校对的全文。原生文字抽取可能丢失数学对象或阅读顺序；OCR 可能把矩阵、分式、上下标、积分界、希腊字母、绝对值和手写笔迹识别错。DOCX 正文文字也可能遗漏嵌入的公式、图形或对象。

每个单元必须区分实际采用的原生抽取、OCR、无可读文本、失败或待核读等状态。OCR 成功仅表示取得文字，不能改称“公式核验通过”。无法读取的页仍登记页序与失败状态，不静默跳过；既有页数与成功抽取页数分别统计。

以下情况必须回看原始 PDF 页面、图片或文档视觉内容：手写板书；公式决定解法或答案；文字/图形不一致；符号、数值或题目条件存在歧义；文本异常稀少；多栏顺序混乱；低识别或跨页断裂。必要时渲染原页核读，而非只看 JSON。只有实际人工核读过的范围可以标注已核读，不能将抽查页推广到全文件。

若核心条件仍无法辨认，明确标出原件、页序与不清之处，请求更清晰的材料或说明不能确定。不得按常见题型、其他版答案或数学常识补猜原文。搜索无命中仅表示当前检索没有找到，不能推出资料不包含该知识点；优先核对抽取覆盖和原页。

## 来源与版本冲突

1. 用户明确指定文件、版本或页序时，先按指定来源核读；若指定路径缺失或对应字节已变，报告并核对，不自动换成类似文件。
2. 完整 SHA-256 相同的文件视为字节副本，只合并派生内容，不删除原件；引用时使用实际读取的原件路径，并保留其他路径关系。
3. 文件名相同但 SHA-256 不同，或“原版/版本 2”“V1.1/V1.2”“最终版”等并存时，全部独立登记。没有用户确认、作者明确勘误或可追溯发布说明，不自行选为最新或正确版本；修改时间、名字与排序不能充当版本证明。
4. PDF 与 DOCX、讲义与详解板书、合并版与分课版是不同材料，不因同题材而认定重复或等价。用页级内容核对后才能建立覆盖、配套或差异关系；PDF 与 DOCX 的题号、公式和条件不默认一致。
5. 试卷和答案需要核对年份、考种、题号、题目条件与版本后再配对。同年月考的“新试卷”“全新版”不得自动套用另一版答案。
6. 来源结论冲突时同时指出各自原件和页序。可以另做数学检验并标为自己的推导，但不能悄悄改写原文或把推导冒充作者勘误；无法判定时保留冲突，向用户询问。
7. 年份、考种、章节与现行考试范围以原文和明确来源为准。当前存在 2024 真题与版本 2、多个版本号月考试卷、跨考种板书和未注明考种材料；不凭目录或文件名宣称已核成纯数二或已核验最新大纲。
8. `91_重复副本/` 和 `math-150/` 中的相同内容可作为原件位置关系登记，但检索默认优先给出非归档的学习资料位置。这只改变显示顺序，不授予更高内容权威。

## 维护与验收

原文件不修改、不移动、不重命名、不重新排版；索引文件只在已授权范围内维护，不默认联网、上传或安装依赖。`math-150/` 及其内部文件保持不变；其 `MANIFEST.json` 引用的 35 份外层源 PDF 保持原路径，因为发布校验脚本按 `ROOT.parent / entry['path']` 读取这些原件。

新增文件独立登记并计算完整哈希。路径失效、字节变化、页数变化、抽取器变化或补充 OCR 时，重新核对关联的全文、摘要和主题入口，不将旧摘要挂到新原件上。顶层导航只在入口、资料域、来源权威、版本关系或边界变化时更新，不持续追加逐文件摘要。

验收分别检查原件清单与哈希、`Fxxxx` 覆盖、内容标识关联、页/区段覆盖、失败记录、索引路径、代表性检索及原文核读流程。须报告缺失与失败数，不能只报成功数。结构通过、全文已抽取、OCR 已取得、摘要已生成、实际页面核读和数学公式正确性各是不同层次；没有做的层次明确保留为未核验。

最终回答以用户问题为中心，简要附实际依据文件与准确页序/区段，必要时说明版本冲突和文字识别缺口。不要以很长的检索清单代替答案，也不要让“节省 token”变成少读核心证据。
